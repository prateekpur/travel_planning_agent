Extract one trip request from the user query. Return a single JSON object and nothing else: no markdown, no explanation.

Use exactly these fields:

{
  "destination": "country or region",
  "days": 1,
  "adults": 1,
  "children": 0,
  "budget": {
    "amount": 6500,
    "maximum": null,
    "currency": "CAD",
    "type": "approximate",
    "includes": [],
    "excludes": []
  },
  "cities": [],
  "travel_style": "relaxed | balanced | adventure | cultural | luxury",
  "walking_level": "low | moderate | high",
  "requirements": {
    "hard_constraints": [],
    "soft_preferences": [],
    "interests": []
  }
}

Rules:

- destination is the country or region. Trim surrounding whitespace.
- days is optional. When stated, it is an integer of at least 1. Read an explicit count such as "7-day", "7 days", or "around 10 days". A week is 7 days, so "two weeks" is 14. If the query gives a date range, count every calendar date from the start date through the end date. A month or season, such as "next March", is not the trip length. Use null when the query does not name a length.
- adults is the number of travelers who are not children. It is at least 1 when stated. Treat number words such as "two" as digits. A singular traveler counts as 1 adult: "I", "I'm", "me", or "my trip" with no other party size means adults is 1. "I want to travel to Thailand" means adults is 1. Use null only when the query says "we" or "us" and does not give a count.
- children is optional. When stated, it is an integer of 0 or more. "kid", "kids", "child", "children", "boy", "boys", "girl", "girls", "son", and "daughter" all mean children. "me, my wife and our two boys" is 2 adults and 2 children. When the traveler is singular ("I") and children are not mentioned, children is 0. Use null when a group is mentioned without saying whether any children are included.
- budget is optional. Use null when the query does not name a budget. When stated, budget is an object, not a number. amount is a number greater than 0 with symbols and thousands separators removed ("C$6,500" is 6500). currency is a 3-letter ISO code in uppercase, read next to the amount ("6500 CAD") or from a symbol prefix: C$ is CAD, US$ is USD, A$ is AUD, NZ$ is NZD, € is EUR, £ is GBP. A bare "$" does not name a currency, so currency is null. type is "approximate" when the query says around, about, approximately, or roughly. Otherwise type is "exact". maximum is the ceiling when the query says up to, no more than, at most, maximum, or under. "about C$5,000, no more than C$6,000" has amount 5000 and maximum 6000. If the query only gives a ceiling, put that number in maximum and leave amount null. Use null for maximum when no ceiling is stated. includes lists costs the budget covers, such as flights or hotels. excludes lists costs it leaves out. Use [] for includes or excludes when the query does not say.
- cities is an array of city names. Split lists joined by commas and "and". Drop blank names. Use [] when no cities are named.
- travel_style is optional. When stated, it must be one of: relaxed, balanced, adventure, cultural, luxury. Use null when the query does not name a style.
- walking_level is optional. When stated, it must be one of: low, moderate, high, read from a phrase about walking such as "moderate walking". Use null when the query does not name a walking level.
- requirements holds other things the traveler stated that are not already stored in the fields above. Do not repeat destination, days, party size, budget, cities, travel style, or walking level. Keep each item as a short phrase from the query. Use [] for a category the query does not mention. Do not invent items.
  - hard_constraints are non-negotiable. Words such as must, cannot, no, or never belong here, such as "no red-eye flights" or "must be wheelchair accessible". A month, season, or date the trip must happen is a hard constraint. "next March" and "in March" mean "travel in March".
  - soft_preferences are wants that can be dropped, such as "prefer vegetarian meals" or "rather not take long bus rides".
  - interests are subjects or activities the traveler wants to spend time on, such as "temples", "street food", or "beaches".

When destination is not stated, set that field to null. Do not invent a destination, a budget, or a city. A singular "I" is one adult, not a guess.
